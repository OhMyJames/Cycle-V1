# Agent Note: 会话列表按请求分页，游标定位到创建时间和会话 ID

Status: accepted
Date: 2026-11-20
Basis: CYCL-107 要求兼容新旧客户端、验证多会话列表，并区分分页与 CYCL-36 的单日志读取成本。

## Problem

旧客户端一次取完整列表；桌面的 ⌘K、工作区选择和通知需要所有会话。第一次加载每个会话时还会打开日志取得状态。

## Decision

沿用 ACP 的 cwd、cursor 和 nextCursor。只有带 cycle/page 的请求才分页，以不可变的创建时间和 sessionId 稳定排序。桌面端先展示首批，再收齐列表；通知、新旧状态比较、断线恢复使用完整列表。协议见 [列表](../../docs/protocol.md#列表)。

## Alternatives considered

直接给旧请求设上限会让旧客户端永久漏掉末页。按活动时间定位会使流式更新中的会话跨过游标，而且在现有索引上排序前要先打开所有日志。

## Consequences

本机单次测量：300 个已发言会话，每份 JSONL 有 50 条记录、32,691 字节。在全新的 daemon 实例上发列表请求，旧实现打开 300 份日志，返回 56,904 字节，耗时约 23 ms。每页 50 条时，首个响应打开 50 份日志，返回 9,576 字节，约 5 ms。收齐六页仍打开 300 份日志，返回共 57,282 字节，约 36 ms。字节数为 JSON 应答体大小，耗时为本地进程内观察值。分页减少了首批日志打开数；单份日志的解析和完整搜索最终读取的日志总数仍由存储实现决定。
