# 0005 以 ACP v2 为蓝本,L1 自己定义类型

状态:已接受(方案 C)

## 决定

- L2 以 ACP v2 为主要参考,不以 v1 为基础。
- L1(客户端到 daemon)的消息模型以 ACP v2 为蓝本,字段和语义保持一致,**不另造一套事件模型**。类型用 zod 自己定义并固定版本,放在 `packages/acp`。
- daemon 转发 agent 的消息,并补充 Cycle 自己的能力。扩展放在 `_cycle/*` 方法和 `_meta` 里,不重复定义 ACP 已有的概念。
- daemon 负责事件日志和重连补发(见 [0002](0002-session-persistence.md)),这是 ACP 没有定义的部分。

## 原因

- 老项目 old-cycle 曾自有一套 wire 协议,被否掉了,因为它在重述 ACP。我们也不重复这个做法。
- 老项目直接把 ACP v2 暴露给客户端,结果 ACP 草案一变,UI 也要跟着改。
- 折中:概念和 ACP 一致,但 schema 由我们自己固定版本,变化在一个包里吸收。

## 风险

- v2 是草案(alpha),schema 可能不兼容变动。升级时 schema、适配和 daemon 一起检查。
- v2 没有定义重连、恢复和传输,这些由 L1 自己定义。
- 与 ACP 保持字段一致,意味着升级 ACP 时要人工对照差异。
