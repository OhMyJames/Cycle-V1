# 0012 附件字节落盘:日志里只留引用,读出时还原

状态:已接受(2026-11-18)。接着 0010 的"以后怎么换":协议和客户端看到的内容不变,变的只是 daemon 怎么存。

## 背景

0010 让附件以 base64 内联走 `session/prompt`,也就内联写进了 JSONL。一张 5 MiB 的图让日志大约涨 7 MiB,而日志每次 `session/resume` 都要整个读、整个重放(远程时还要过 SSH),agent 回显的图片也一样。

## 决定

1. **在存储接口之后做**:`BlobLogStore` 包住任意 `LogStore`,`SessionLog.append` 把记录里的大字节换成引用,`read` 和 `subscribe` 再放回去。daemon 其余代码、协议和客户端都看不出区别:重放和实时广播里的图片块还是带 `data`(桌面端的界面就是这样读的)。
2. **换哪些**:记录里任何深度的 `image` 块的 `data`,和嵌入资源的 `blob`,base64 文本不小于 16 KiB 时。更小的留在日志里,不为几 KB 建文件。
3. **引用的形状**:字段置为 `""`,所在对象(image 块或 resource)的 `_meta["cycle/blob"]` 记 `{ field: "data" | "blob", sha256, bytes }`。`sha256` 是 base64 文本的哈希,文件内容就是那段文本,所以还原后与原来逐字节相同。
4. **放哪**:`<数据目录>/blobs/<会话 id>/<sha256>`,目录 0700、文件 0600,先写临时文件再改名,**先于**日志行写入(日志里不会有指向不存在文件的引用)。**每个会话一个目录,不共享**:删除会话"永久移除记录"(AGENTS.md 红线),整个目录随之删掉;共享存储就得做跨会话的垃圾回收。同一会话内相同内容只存一份。
5. **旧日志**:内联 `data` 的旧记录照常读,只有带引用的才还原。
6. **文件丢了**:不让整份日志不可读。那一块还原为 `data: ""`,`_meta["cycle/blobMissing"]: true`,其余照常。哈希名只接受 64 位十六进制,日志里被改过的引用不会指到别的路径。

## 为什么不是别的

- 回放只给引用、客户端再按需取:要新增一个取字节的方法,而且现在的界面直接读重放里的 `data`,会坏。可以以后作为可选模式加,不需要改存储。
- 全局共享的内容寻址存储:去重省不了多少(用户很少把同一张图发到多个会话),却引入跨会话回收。
