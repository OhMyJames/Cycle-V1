# Cycle 的界面品味

Cycle 是一个人每天开几个小时的工具:盯着 agent 干活、批准它的操作、回看它做了什么。所以界面的标准是
**安静、清楚、密度合适、键盘能走完**,不是"好看的页面"。这里没有首屏、没有营销区块、没有装饰。

一句话的判断标准:用户的注意力应该在 agent 在做什么上,界面本身不该被注意到,除非它出了问题,那时它要立刻说清楚
出了什么问题、该做什么。

> 这份 skill 的方法借自 tasteskill(去模板味、一个系统、真图标、先写文案、动效要有理由、用真实浏览器检查),
> 内容按 Cycle 重写:它原本做公司官网,这里只留适用于工具型桌面应用的部分。

## 开始之前

1. 读根目录的 `DESIGN.md`(这个应用该是什么样子:颜色、字阶、间距、组件、状态;标"提议"的还没确认,不要当成已定),
   再读 `packages/ui/AGENTS.md`、`docs/desktop.md` 的界面部分,以及 ui-sdk skill(`packages/ui/.claude/skills/ui-sdk`)。
2. 读 `packages/ui/src/styles/app.css`:现有的 `data-slot`、间距和颜色就是这个系统,新东西接在它后面,不另起一套。
3. 动手前用三行写清:**谁在什么时候用这块**(例如"agent 在等批准,用户从别的窗口切回来");**它有哪些状态**
   (`references/states.md`);**哪里要动、为什么动**(没有理由就不动)。

## 硬规则

这十条压过其余所有内容。

1. **只用令牌。** DESIGN.md 里的 `--cycle-*` 加 ui-sdk 的 `--ui-*`(门禁检查 DESIGN.md 与 `app.css` 的 `--cycle-*` 一致:新增令牌要两边都写)。 颜色只写 `var(--ui-*)`,圆角 `var(--ui-radius)`(8px,`app.css` 里设的;不要给个别组件另写圆角值),间距 `var(--cycle-gap)` 或 `--ui-spacing` 的倍数。不写十六进制颜色、
   不加新的强调色、不加渐变、毛玻璃、发光、阴影装饰。令牌用 `light-dark()`,跟随系统深浅色;每一处都得跟着换,深浅色都要看。
2. **一个系统。** 根字号 14px(`app.css`),其余用 `em` 相对它(ui-sdk 的 `--ui-font-size` 是 13px,组件内部用它);一种字体栈(系统字体),等宽只用于代码、命令、路径、id;
   两种内容宽度(侧栏、主区),主区里的对话有最大行宽。不新增字号、不新增圆角值、不新增间距值。
3. **样式写在 `app.css` 里,用 `data-slot`。** 我们自己的组件不用 Tailwind 工具类,不用行内样式。Tailwind 只服务 Streamdown。
4. **状态要齐。** 每块界面都有:空、加载、出错、断线、内容很长、数量很多。出错时写**原因和下一步**,不写"出错了"。
   (`references/states.md` 有逐块的清单。)
5. **文案平实。** 按钮是动词加对象("Allow once""Delete session");不用感叹号、表情、"powerful""seamless"之类的词;
   不编数字和名字;源语言是 en-US(句首大写,其余小写),文字写在 `packages/ui/src/messages/en-US.ts`,组件里用 `t("key")`,不在标记里写字面量;整句,不拼句;数量用复数消息;数字和日期用 `Intl`。(`references/copy.md`;决定见 `docs/decisions/0012`)
6. **动效只为说明变化。** 120 到 200ms,只动 transform 和 opacity,ease-out,不弹跳;流式文字不让布局跳;
   `prefers-reduced-motion` 下全部静止。(`references/motion.md`)
7. **图标一套。** 用 iconmcp 的线性图标(16 单位网格),`currentColor`,不画仿品;只有图标的按钮必须有名字(`aria-label`)和提示。
   (`references/icons.md`)
8. **键盘走得通。** 每个动作都能不用鼠标完成;焦点环始终看得见(`app.css` 里统一画成 2px 的 `--cycle-accent`;ui-sdk 自己的 `--ui-ring` 浅色下只有 1.3:1,不要用它表示焦点);信息不只在悬停里出现;快捷键写在提示里。
9. **对齐与密度。** 同一列的左边缘对齐;长文本换行或省略(并能看全),代码块自己横向滚动,不撑开页面;
   一屏里同时只有一个主要动作。
10. **不信任内容,也不假装有内容。** agent 的输出不可信(见 `docs/desktop.md`),渲染要走已有的安全路径;
    界面里不放假头像、假数据、占位的"Lorem"、装饰性的统计条或评价。

## 怎么做

1. **读。** 上面三步。
2. **先写文案。** 把这块界面会出现的每一个字写下来(标题、按钮、空状态、错误、确认),按 `references/copy.md` 过一遍,再写代码。
3. **做。** 在 `packages/ui/src/react` 里写组件,样式加进 `app.css`。先让最坏的状态(很长的标题、断线、几百个会话)看起来对,
   再调正常状态。
4. **查。** 按 `references/check.md`:
   - `bun run check`(DOM 测试里加这块的各个状态,这是回归的底线);
   - `bun .claude/skills/cycle-design-taste/scripts/scan-copy.mjs` 扫界面文案;
   - 在真实窗口里看一遍:浅色、深色、窗口最窄和默认大小,键盘从头走到尾。
5. **报告。** 说清:改了什么、看过哪些状态和主题、哪些没看(例如没在 Mac 上看)、留下哪些已知缺口。

## 清单

- 所有颜色来自令牌;深浅色都看过。
- 没有新的字号、圆角、间距值;没有行内样式、Tailwind 类。
- 每个状态都有:空、加载、出错(带原因和下一步)、断线、长内容、多内容。
- 每个按钮是"动词加对象";没有感叹号、表情、空话;`scan-copy.mjs` 没有新增命中。
- 只有图标的按钮有名字;键盘从头走到尾;焦点环不被裁掉。
- 动效有理由、不超过 200ms、尊重 reduced motion;流式输出时页面不跳。
- 长标题、长路径、长命令、宽表格、超长代码行都不撑破布局。
- agent 的输出经过已有的清洗路径;没有新加载外部资源。
- 眼睛看一遍:这块界面像是同一个人做的吗?
